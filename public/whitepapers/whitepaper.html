00 // Foundational Concepts

The Paradigm Shift: From Open-Loop Inference to Closed-Loop Control

Traditional Large Language Model (LLM) serving follows an open-loop feed-forward pipeline. Given an input context, the model computes token probabilities conditioned strictly on preceding context tokens. If generation trajectory deviates during intermediate reasoning steps, errors compound monotonically.

Agentic workflows replace open-loop inference with closed-loop discrete control systems. By treating the foundation model as a stochastic reasoning processor situated within a cyclic state transition graph, we formalize agent execution as:

S_{t+1} = f_{transition}(S_t, A_t, O_t)
A_t = π_{policy}(S_t; θ_{LLM})
O_t = Ε(A_t)

Where S_t represents working memory and environment state, A_t is the structured action (tool call, sub-query, code execution), and O_t is the deterministic observation returned by operational environment Ε.

01 // Design Pattern

The Reflection Pattern: Dual-Agent Evaluator-Critic Loops

Closed-loop iterative refinement utilizing isolated generative and evaluative contexts.

The Reflection pattern decouples generation from quality assurance. A foundational limitation of single-prompt generation is prompt interference: instructing a model to simultaneously brainstorm, draft, check formatting, and verify rigorous constraints degrades performance across all dimensions. Reflection decomposes the cognitive burden into distinct temporal roles:

  • Generator (π_gen): Unconstrained generation focused on creative, analytical, or algorithmic synthesis.
  • Critic / Evaluator (π_eval): Rubric assessment verifying factual grounding, edge-case coverage, and schema fidelity.
  • State Revision Memory: Explicit diffs and structured feedback injected back into the Generator's context window.

02 // Design Pattern

The Tool Use Pattern: Schema-Enforced Function Calling

Grounding probabilistic inference in deterministic compute and external API gateways.

LLMs operate in parametric isolation: weights reflect static historical data and lack access to real-time networks or relational databases. The Tool Use pattern converts the LLM into a deterministic RPC controller. The model generates structured payloads conforming to JSON Schema, and an execution sandbox handles authorization, security controls, and parameter validation.

03 // Design Pattern

The ReAct Pattern: Interleaved Reasoning and Action

Coupling dynamic thought synthesis with environment feedback via persistent scratchpad memory.

The Reason + Act (ReAct) architecture establishes an alternating cycle of internal reasoning and empirical interactions. Without explicit internal tokens (Thought:), agents exhibit action blindness, invoking external endpoints without grounding. Pure chain-of-thought, conversely, lacks environment feedback and drifts into hallucination.

04 // Design Pattern

The Planning Pattern: Directed Acyclic Graph (DAG) Execution

Decomposing complex strategic objectives into dependency graphs with dynamic replanning triggers.

ReAct and Reflection patterns execute sequentially, picking each step greedily. For multi-service migrations or complex architectural tasks, greedy dispatch fails due to horizon myopia. The Planning Pattern decomposes the objective upfront into a Directed Acyclic Graph (DAG) where nodes represent atomic work units and edges encode dependency constraints.

05 // Design Pattern

The Multi-Agent Collaboration Pattern: Hierarchical Topologies

Distributed specialization, message buses, and consensus aggregation across heterogeneous agents.

When tasks demand contradictory persona constraints (such as rapid speculative synthesis versus defensive compliance auditing), cramming all concerns into a single prompt damages performance. The Multi-Agent pattern formalizes agent collaboration into supervisor-worker pools or decentralized topologies using typed message passing.

07 // Hardening Guidelines

Production Hardening: Operational Guardrails

Mitigating failure modes in non-deterministic systems[cite: 5].

01 // Bounded Budgets

Step & Token Deadlines

Enforce a maximum step limit (MAX_STEPS = 10) and hard wall-clock timeouts. Runaway loops exhaust token quotas and increase operational costs without circuit breakers[cite: 5].

02 // Deterministic Types

Pydantic Schemas

Reject raw text strings for inter-agent communication. Require JSON schemas with Pydantic validation to handle structural deserialization errors[cite: 5].

03 // Full Observability

Distributed Tracing

Trace thoughts, tool payloads, and critic scores using distributed telemetry spans (OpenTelemetry). Granular event logs are necessary to debug non-deterministic state transitions[cite: 5].
