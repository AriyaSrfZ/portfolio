00 // FOUNDATIONAL CONCEPTS

The Paradigm Shift: From Open-Loop Inference to Closed-Loop Control

Traditional Large Language Model (LLM) serving follows an open-loop feed-forward pipeline. Given an input context x ∈ X, the model computes token probabilities conditioned strictly on preceding context tokens: P(y | x) = ∏ P(y_t | y_<t, x). If generation trajectory deviates during intermediate reasoning steps, errors compound monotonically. The system possesses zero observability over its runtime errors and zero capacity for self-correction.

Agentic workflows replace open-loop inference with closed-loop discrete control systems. By treating the foundation model as a stochastic reasoning processor situated within a cyclic state transition graph, we formalize agent execution as:

S_{t+1} = f_{transition}(S_t, A_t, O_t)
A_t = π_{policy}(S_t; \theta_{LLM})
O_t = \mathcal{E}(A_t)

Where S_t represents the current working memory and environment state, A_t is the structured action (tool call, code execution, sub-query), and O_t is the deterministic observation returned by the operational environment \mathcal{E}. Below are the five canonical design patterns that govern modern agentic architectures.

01 // DESIGN PATTERN

The Reflection Pattern: Dual-Agent Evaluator-Critic Loops

Closed-loop iterative refinement utilizing separate generative and evaluative context windows.

The Reflection pattern decouples initial generation from quality assurance. A foundational limitation of single-prompt generation is prompt interference: instructing a model to simultaneously brainstorm, draft, check formatting, and verify rigorous constraints degrades performance across all dimensions. Reflection decomposes the cognitive burden into distinct temporal roles:

  • Generator (π_gen): Unconstrained generation focused on creative, analytical, or algorithmic synthesis.
  • Critic / Evaluator (π_eval): Zero-shot rubric assessment strictly verifying factual grounding, edge-case coverage, and schema fidelity.
  • State Revision Memory: Explicit diffs and structured feedback injected back into the Generator's context window.

Algorithmic State Transition

The control flow executes within a stateful reducer. In each iteration k ∈ [1, K_{max}], the Generator receives the prompt combined with historical critiques \mathcal{H}_k = \{(D_1, C_1), \dots, (D_{k-1}, C_{k-1})\}. The critic evaluates against a structured rubric \mathcal{R} = \{r_1, r_2, \dots, r_m\} using strict JSON-schema enforcement:

reflection_loop.py 
from typing import TypedDict, List
from pydantic import BaseModel, Field
from langchain_core.prompts import ChatPromptTemplate

class CritiqueReport(BaseModel):
    score: float = Field(..., ge=0.0, le=1.0, description="Comprehensive quality metric.")
    identified_flaws: List[str] = Field(default_factory=list)
    remediation_directives: List[str] = Field(default_factory=list)
    is_terminal_pass: bool = Field(..., description="True if satisfies criteria.")

class ReflectionState(TypedDict):
    task: str
    current_draft: str
    critiques: List[CritiqueReport]
    iteration_count: int
    max_iterations: int

def generator_node(state: ReflectionState, llm) -> dict:
    """Generates or revises the output conditioned on historical critiques."""
    critique_context = "\n".join([
        f"- Flaws: {c.identified_flaws} | Action: {c.remediation_directives}"
        for c in state["critiques"]
    ])
    prompt = ChatPromptTemplate.from_messages([
        ("system", "You are an expert engineer. Fulfill task instructions strictly."),
        ("user", "Task: {task}\nHistory Critique:\n{critique_context}\nCurrent draft:\n{draft}")
    ])
    response = (prompt | llm).invoke({
        "task": state["task"],
        "critique_context": critique_context,
        "draft": state.get("current_draft", "")
    })
    return {"current_draft": response.content, "iteration_count": state["iteration_count"] + 1}

def evaluator_node(state: ReflectionState, critic_llm) -> dict:
    """Evaluates candidate output against quality and edge-case rubrics."""
    structured_critic = critic_llm.with_structured_output(CritiqueReport)
    evaluation: CritiqueReport = structured_critic.invoke(
        f"Audit this output against requirements:\nOutput: {state['current_draft']}"
    )
    return {"critiques": state["critiques"] + [evaluation]}
Production Failure Mode

Critique Saturation: Without strict termination predicates, generator and critic often enter an oscillation trap, continually rewriting syntax without improving semantic veracity.

Cost & Latency Trade-off

Increases token consumption by 2.5x – 4.8x per request and multiplies wall-clock time linearly with iteration limit K_{max}.

02 // DESIGN PATTERN

The Tool Use Pattern: Schema-Enforced Function Calling

Grounding probabilistic reasoning engines in deterministic computation, persistent data stores, and real-world APIs.

LLMs operate in parametric isolation: their weights reflect past world state, and they lack native execution contexts for arithmetic, relational databases, or real-time web retrieval. The Tool Use pattern converts the LLM into a deterministic RPC controller. The model generates structured JSON conforming to a JSON Schema specification, and a runtime environment handles invocation, security sandboxing, and output serialization.

from langchain_core.tools import tool
from pydantic import BaseModel, Field
import json

class DatabaseQuerySchema(BaseModel):
    query: str = Field(..., description="PostgreSQL SELECT query strictly read-only.")
    timeout_seconds: int = Field(default=5, le=30)

@tool(args_schema=DatabaseQuerySchema)
def execute_sql_query(query: str, timeout_seconds: int = 5) -> str:
    """Executes validated SQL against read-replica with parameter isolation."""
    if any(token in query.upper() for token in ["DROP", "DELETE", "UPDATE", "INSERT"]):
        raise PermissionError("Mutation operations forbidden on read-replica.")
    # Mock execution payload for demonstration
    return json.dumps([{"status": "success", "rows": 124, "latency_ms": 14.2}])

def dispatch_tool_call(tool_call: dict, tool_registry: dict) -> dict:
    """Dispatches LLM-emitted tool calls to isolated sandbox runtime with structured logging."""
    name = tool_call["name"]
    args = tool_call["args"]
    call_id = tool_call["id"]
    
    if name not in tool_registry:
        return {"tool_call_id": call_id, "output": f"Error: Unknown tool {name}"}
    
    try:
        result = tool_registry[name].invoke(args)
        return {"tool_call_id": call_id, "output": result, "status": "200_OK"}
    except Exception as exc:
        return {"tool_call_id": call_id, "error": str(exc), "status": "500_RUNTIME_ERROR"}
03 // DESIGN PATTERN

The ReAct Pattern: Interleaved Reasoning and Action

Coupling dynamic task reasoning with real-time environment feedback via persistent scratchpad memory.

Introduced by Yao et al., the Reason + Act (ReAct) architecture establishes an alternating cycle of internal monologues and empirical interactions. Without explicit reasoning tokens (Thought:), agents suffer from "action blindness"—invoking external tools with ungrounded parameters. Conversely, pure Chain-of-Thought (CoT) reasoning lacks environmental grounding and quickly drifts into speculative hallucinations.

import re
from typing import Tuple, Optional

REACT_PROMPT = """Answer the objective step-by-step. You have access to: {tool_names}.
Follow this exact format:
Question: the input request
Thought: consider what steps to take next
Action: the action to take, exactly one of [{tool_names}]
Action Input: input parameters to the action
Observation: the result of the action
... (this Thought/Action/Action Input/Observation can repeat N times)
Thought: I have determined the complete final response
Final Answer: the final answer to the original question

Question: {question}
{scratchpad}"""

def parse_react_output(llm_output: str) -> Tuple[Optional[str], Optional[str], Optional[str]]:
    """Parses model generation into Thought, Action, and Action Input."""
    if "Final Answer:" in llm_output:
        final_answer = llm_output.split("Final Answer:")[-1].strip()
        return None, None, final_answer
    
    regex = r"Action:\s*(.*?)\nAction Input:\s*([\s\S]*)"
    match = re.search(regex, llm_output)
    if not match:
        raise ValueError("Failed to parse ReAct action grammar.")
    
    action = match.group(1).strip()
    action_input = match.group(2).strip()
    return action, action_input, None
04 // DESIGN PATTERN

The Planning & Decomposition Pattern: Directed Acyclic Graph Execution

Macro-strategic goal decomposition into directed dependency graphs with dynamic replanning triggers.

ReAct and Reflection patterns execute greedily—they select step t+1 based on immediate feedback. For complex distributed tasks (e.g., repository migration, multi-service benchmarking), greedy generation fails due to horizon myopia. The Planning Pattern enforces upfront structural decomposition: constructing a Directed Acyclic Graph (DAG) G = (V, E) where vertices V represent atomic task units and edges E encode dependency constraints.

from typing import List, Dict
from pydantic import BaseModel, Field

class PlanStep(BaseModel):
    step_id: int
    description: str
    dependencies: List[int] = Field(default_factory=list)
    assigned_tool: str
    status: str = "PENDING"  # PENDING | RUNNING | COMPLETED | FAILED

class ExecutionDAG(BaseModel):
    plan_id: str
    steps: Dict[int, PlanStep]

    def get_executable_steps(self) -> List[PlanStep]:
        """Identifies steps whose prerequisite dependencies are satisfied."""
        executable = []
        for step in self.steps.values():
            if step.status == "PENDING":
                parents_done = all(
                    self.steps[dep].status == "COMPLETED" 
                    for dep in step.dependencies
                )
                if parents_done:
                    executable.append(step)
        return executable

    def mark_step_result(self, step_id: int, success: bool) -> bool:
        """Updates state and signals if replanning is mandatory."""
        if success:
            self.steps[step_id].status = "COMPLETED"
            return False
        else:
            self.steps[step_id].status = "FAILED"
            return True  # Triggers replanning controller
05 // DESIGN PATTERN

The Multi-Agent Collaboration Pattern: Hierarchical & Network Topologies

Distributed specialization, inter-agent message buses, and consensus aggregation across heterogeneous models.

When tasks demand contradictory persona constraints (e.g., rapid speculative synthesis vs. defensive security auditing), cramming all concerns into a single prompt damages performance. The Multi-Agent pattern formalizes agent collaboration into either hierarchical supervisor-worker pools or decentralized communication topologies using typed message passing.

multi_agent_supervisor.py 
from typing import Literal
from pydantic import BaseModel
from langchain_core.prompts import ChatPromptTemplate

class RouterSchema(BaseModel):
    next_worker: Literal["ResearchAgent", "CoderAgent", "AuditorAgent", "FINISH"]
    delegation_rationale: str

def supervisor_router_node(state, supervisor_llm) -> RouterSchema:
    """Orchestrates work among specialized autonomous agents."""
    system_prompt = (
        "You are an engineering team lead. Given the current progress, select "
        "the single best agent to handle the next phase of work. "
        "Choose 'FINISH' once the objective is fully satisfied."
    )
    prompt = ChatPromptTemplate.from_messages([
        ("system", system_prompt),
        ("user", "Current Task: {task}\nCompleted State: {messages}")
    ])
    structured_llm = supervisor_llm.with_structured_output(RouterSchema)
    return (prompt | structured_llm).invoke(state)

07 // ENGINEERING STANDARDS

Production Hardening: Mitigating Failure Modes

Operational guardrails for deploying non-deterministic cognitive loops into production.

01 // Bounded Budgets

Step & Token Deadlines

Always impose a strict hard bound on cycles (MAX_STEPS = 10) and total wall-clock timeout. Runaway agent loops will quickly exhaust rate quotas and inflate API invoices without hard circuit breakers.

02 // Deterministic Types

Pydantic Schemas

Never accept raw Markdown or loose strings for agent-to-agent communication. Use structured JSON output with strict Pydantic validation. Re-prompt automatically on schema validation errors.

03 // Full Observability

OpenTelemetry & Tracing

Instrument every thought, tool call payload, and critic evaluation with distributed tracing spans (OpenTelemetry, LangSmith, Phoenix). You cannot debug non-deterministic state machines without granular event replays.
